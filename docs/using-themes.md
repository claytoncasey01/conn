# Using themes

- **Picking a look.** The `Theme` button in the header opens the theme menu: a dropdown of every installed theme, a Light / Dark / System control (System follows the OS and changes with it), the accent swatches for a theme with a free accent (or a Variant picker for a theme that ships named variants), and an Effects switch for the theme's animated effects (on unless your system asks for less motion, until you switch it on or off yourself). The choice is kept in this browser. A fresh install, and everyone after this upgrade, starts on Default in System mode; Neon, the original look, is in the dropdown.
- **Built-in looks.** Default, Neon, Matrix and CRT are built in. CRT has Green, Amber and White variants. The Effects switch also governs CRT's static scanlines and vignette: they still draw with Effects on under reduced motion, the flicker never does, and Matrix's rain draws one still frame. The rain's glyph font, `src/effects/fonts/matrix-code/`, is SIL OFL 1.1, not this repo's license.
- **Where themes live.** A theme is a folder with a `theme.json` (its tokens) and, optionally, a `theme.css`. Built-in themes are in `themes/` in this repo; your own go in `~/.conn/themes/<id>/` (`$CONN_DATA/themes` when `CONN_DATA` is set) and show up in the dropdown without a rebuild. A theme of your own that has a `theme.css` asks before it is used the first time, and again when the file changes; a built-in's never does.

## The gallery

- **The gallery.** The `Themes` page lists themes from a public GitHub repo (`claytoncasey01/conn-themes` by default; `CONN_THEME_INDEX=owner/repo` points it at another, and a value that is neither `owner/repo` nor one of the off-values below falls back to the default repo) and installs, updates and uninstalls them from there. What it touches, because a theme is somebody else's file:
  - It reads `https://raw.githubusercontent.com/<themeIndex>/...` and nothing else, with plain GETs that carry no token, no cookie and nothing of yours: the index (`/main/index.json`) when the Themes page opens, and one theme file (`/<commit>/<id>/theme.json`, at the commit the index pins) when `Install` or `Update` is clicked (which also reads the index again, uncached). A redirect is never followed, a read gives up after 10 seconds, and the index is read at most once a minute (a failed read is retried after 5 seconds), however many tabs are open.
  - The index is capped at 512 KB (over that it is refused whole, not read past the cap) and a theme file at 64 KB, entries beyond the first 500 are ignored, and an entry with any bad id, commit, hash, file list or manifest is dropped and counted, never installed. An install refuses a file that does not hash to the index's `sha256` or fails the same checks as a theme of your own, contrast included, and a gallery theme is `theme.json` alone: no stylesheet of its own is ever served.
  - `Install` and `Update` write `<dataDir>/themes/<id>/theme.json` and `.source.json` (the repo, the commit, the hash and the time): into a temporary folder first, renamed into place, so a failure leaves the old theme as it was (an `Update` first moves the old folder aside as `.tmp-<id>-...-old-...` in the same folder and removes it once the new one is in place; it is kept, and named in the error, only if putting the old one back fails). They never replace a folder of yours that has no `.source.json`, or a built-in's id.
  - `Uninstall` removes only a real folder that has a `.source.json` file; a folder of your own, a link or anything else is refused.
  - The previews on the page are drawn from the index's tokens in sandboxed frames (no scripts, no network), and the install and uninstall requests need the `x-conn: 1` header, as the other POSTs do.
  - `CONN_THEME_INDEX=off` turns all of it off: nothing is fetched, the page says the gallery is off, and the install and uninstall routes answer 404. Themes already installed stay, and work like any theme of yours. The values that turn it off are `off` (or `false`, `0`, `none`, `no` or `disabled`, in any case); any other value that is not `owner/repo` is not an off-switch and reads the default repo.
